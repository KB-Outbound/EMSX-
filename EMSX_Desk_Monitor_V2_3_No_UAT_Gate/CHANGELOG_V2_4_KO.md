# 2.4 안정성 개선

## 주요 변경

- Bloomberg 작업자에서 연결·구독 종료를 감지하고 1초부터 최대 30초까지 지수 대기와 무작위 지연을 적용하여 재연결합니다. 중지 요청은 대기를 즉시 중단합니다. 연결 시도 제한 시간은 3초이며 이벤트 조회 간격은 50밀리초입니다. 이는 전체 서비스 시작 시간의 상한을 보장하지는 않습니다.
- 재연결마다 세션, 저널 연결, 주문·라우트 구독, 순번, 초기 스냅샷 상태를 새로 생성합니다. 화면도 새 스냅샷으로 재구성합니다. 자동 Ack는 해제 상태로 시작하며 운영자가 다시 활성화해야 합니다. 이전 세션에서 대기 중이던 활성화 명령은 폐기합니다.
- 주문 장부, Ack 엔진, SQLite 연결의 공개 연산을 재진입 잠금으로 보호합니다. SQLite의 고유 키와 전송 전 영속 예약을 유지하여 동일 DB를 사용하는 호출 간 중복을 차단합니다. 전송 콜백보다 먼저 응답 추적 정보를 등록하여 즉시 응답의 상태를 덮어쓰지 않습니다.
- 수량·주문 번호에 소수, 무한대, 비수치 값이 들어오면 차단합니다. 초기 스냅샷, 활성화 이전 주문과 후속 부분 갱신에 대한 자동 승인 금지를 유지합니다.
- 자동 전송 전에 감사 기록을 쓰고 디스크 동기화를 요청합니다. 기록 실패 시 전송하지 않습니다. 전송·응답·타임아웃·차단·해제도 감사 기록에 남깁니다. 네트워크 전송 뒤 기록 실패나 연결 단절은 결과 불확실로 처리하고 자동 재시도하지 않습니다.
- 화면 큐는 최대 10,000개로 제한합니다. 100밀리초 안에 전달하지 못하면 Ack를 차단하고 세션을 재연결하여 화면을 다시 동기화합니다. 과부하 중 모든 화면 이벤트의 개별 보존을 보장하지는 않습니다. 자동 조치 감사 기록과 영속 예약은 별도로 유지합니다.
- 화면은 한 번에 최대 20밀리초 동안 큐를 처리하고, 잔여 메시지가 있으면 10밀리초 후 다시 처리합니다. 메시지 순서를 유지하며 부분 갱신을 임의로 합치지 않습니다. 동기식 감사 저장은 전송 안전성을 우선하므로 실제 장비에서 지연을 측정해야 합니다.
- 순번 경고와 활동 이력은 최근 300개로 제한합니다. Ack 중복 추적은 세션당 최대 100,000개 주문까지 유지하며 한도 도달 시 신규 주문 추적과 Ack를 차단합니다. 안전성을 위해 오래된 중복 키를 임의 삭제하지 않습니다. 현재 장부의 주문·라우트와 디스크 감사 기록은 자동 삭제하지 않습니다.
- 종료 시 대기 요청을 불확실 상태로 기록하고 세션·DB·메모리 참조를 정리합니다. 화면 종료는 작업자 정리가 끝날 때까지 비동기로 기다립니다.

## 호환성과 이관

기존 관리자 JSON 키, 기본 비활성 설정, SQLite 테이블과 고유 키를 유지합니다. DB 초기화나 설정 변경은 필요하지 않습니다. 추가된 `AUDIT_FAILED` 상태는 전송 전에 감사 기록이 실패한 경우입니다. 기존 `RESERVED`, `SENT`, `UNKNOWN` 등은 자동 재시도하지 않습니다. 운영자가 EMSX와 직접 대조해야 합니다.

배포 시 `synchronization.py`도 함께 복사하십시오. 실행 중인 기존 프로그램을 정상 종료하고 기존 저널·설정·감사 기록을 보존한 뒤 교체하십시오. 재연결은 자동 Ack를 재활성화하지 않습니다. 생산 전송 승인이나 Bloomberg 권한 설정을 자동으로 변경하지 않습니다.

엔진의 기존 공개 속성은 호환성을 위해 유지합니다. 병렬 호출에서는 공개 메서드를 사용하고 `orders`, `seen`, `pending` 등의 내부 컬렉션을 직접 변경하지 마십시오. 관리자 설정도 실행 중 다른 스레드에서 직접 변경하지 마십시오. 알림·전송 콜백은 상태 잠금 안에서 순서대로 실행되므로 다른 스레드의 엔진 호출 완료를 기다리는 콜백은 사용하지 마십시오.

서로 다른 PC와 별도 DB 사이의 중복 방지는 제공하지 않습니다. 승인된 단일 전송자를 유지하십시오. 감사 파일은 계좌 정보의 전체 사본 대신 환경·팀·주문 번호·조치·시각·결과를 기록합니다. 파일 보관 기간과 접근 권한은 데스크 운영 정책에 맞게 관리해야 합니다.

## 검증

프로젝트 폴더에서 Python 3.10 이상으로 실행합니다.

```bash
python -m unittest discover -s tests -v
```

기존 45개와 추가 14개, 총 59개 테스트가 통과했습니다. 추가 검증은 동시 중복 호출 2,000회, 공유 SQLite 예약 경합, 즉시 응답, 감사 저장 실패, 응답 시간 초과, 종료 후 호출, 숫자 검증, 추적 한도, 큐 과부하, 지수 재연결, 중지 응답, 오프라인 데모 스냅샷, 병렬 장부 갱신 10,000건, 실제 파서를 거치는 모의 구독 버스트 5,000건과 단절·정리를 포함합니다. 이는 처리량이나 지연 시간의 운영 보증 수치가 아닙니다.

블룸버그 터미널 및 Windows 화면 환경이 없는 Linux에서 검증했습니다. 실제 BLPAPI 세션, 전송 권한, SellSideAck, Windows 실행 파일과 화면 동작은 검증하지 않았습니다. 배포 전 승인된 BETA 환경에서 연결 단절·복구, 화면 응답성, 감사 파일 권한, 피크 부하와 실제 응답을 확인해야 합니다. 테스트는 실제 주문을 승인하거나 외부로 전송하지 않습니다.

## 2.4.1 화면 현지화

- 창·상단 제목과 Windows 제품명·파일 설명을 요청된 부서·담당자 표기로 통일했습니다.
- 하단 문의처를 고정 표시하고 표·입력창·탭·로그를 다크 테마로 변경했습니다.
- 운영 버튼·상태 안내·확인창·CSV 저장 안내를 한국어로 정리했습니다.
- 불필요한 화면 문구를 제거하되 실제 주문 변경 확인과 권한 안내는 유지했습니다.
- 거래 용어와 내부 API·상태 코드·기존 설정을 보존하고 표시 계층에서만 번역합니다.
- 기존 59개 테스트 및 Python 컴파일 검사를 통과했습니다. Windows 실행 파일 생성과
  실제 화면 렌더링은 현재 환경에서 검증하지 않았습니다.


## 2.4.2 데스크 표시 및 필드 보완

- Sequence를 Order·Route·자동 수신확인 표와 CSV에서 제거하고 내부 안전 검사에는 유지했습니다.
- EMSX_STATUS 기반 Line Status와 EMSX_HAND_INSTRUCTION 기반 Instruction을 표시합니다.
- Assign·Cancel·Part-filled 상태 및 Instruction의 부분 갱신 보존을 검증했습니다.
- 경고 문구를 Route 미지정·미체결 정체로 통일하고 관측 시간 안내를 정리했습니다.
- 담당자명은 최상위 창 제목과 제품 정보에만 유지하며 실행 환경 제목과 하단에서 제거했습니다.
- 총 62개 테스트, 컴파일 검사와 수정 모듈 정적 검사를 통과했습니다.


## 2.4.3 KB 색상 체계 및 표 스타일

- 차콜 배경과 KB Yellow 강조색을 공통 테마 모듈로 통합했습니다.
- 주요 버튼·선택 탭·지표·상태 배지와 비활성·오류 상태의 색상을 구분했습니다.
- 표의 행 높이·머리글 여백·교차 배경·테두리·가로 스크롤을 정리했습니다.
- 상태별 행 강조를 추가하고 값 변경 없이 경고나 정렬만 바뀌는 경우도 갱신합니다.
- 제목·현지화·기존 전송 안전장치는 유지했습니다.
- 기존 테스트 62개, 컴파일·정적 검사를 통과했습니다. 실제 화면 렌더링과 Windows 빌드는 미검증입니다.


## 2.5.0 거래일·Basket·고객 비고와 알림

- 오늘·전일 Create Time 필터, 날짜 누락 집계, 생성 시각·Basket 기준 정렬을 추가했습니다.
- Instruction을 EMSX_NOTES 고객 비고로 교정하고 처리 방식 플래그는 제외했습니다.
- Basket Name 열·검색·그룹 정렬을 추가하고 Route·Broker·자동 Ack 표에 날짜 범위를 적용했습니다.
- Unrouted Warning과 No-Fill Alert를 분리하고 Ack 대기·부분 체결·종료 상태의 오탐을 줄였습니다.
- 시각 배지와 비동기 경고음을 연결하고 반복·재발·음향 해제·정지 시 중단을 구현했습니다.
- 자동 Ack 버튼명을 줄이고 기본 환경을 PROD로 변경했습니다. DEMO 전용 실행 경로는 유지합니다.
- 날짜 범위 밖·날짜 미확인 신규 주문의 자동 Ack를 차단합니다. DB 스키마와 기존 설정은 유지합니다.
- 기존 테스트 62개와 신규 11개, 총 73개를 통과했습니다. 원본 데이터와 실제 UI·음향의 운영 검증 범위는 README에 명시했습니다.
