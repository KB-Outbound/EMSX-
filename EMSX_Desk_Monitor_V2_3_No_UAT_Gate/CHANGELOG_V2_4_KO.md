# 2.4 안정성 개선

## 주요 변경

- Bloomberg 작업자에서 연결·구독 종료를 감지하고 1초부터 최대 30초까지 지수 대기와 무작위 지연을 적용하여 재연결합니다. 중지 요청은 대기를 즉시 중단합니다. 연결 시도 제한 시간은 3초이며 이벤트 조회 간격은 50밀리초입니다. 이는 전체 서비스 시작 시간의 상한을 보장하지는 않습니다.
- 재연결마다 세션, 저널 연결, 주문·라우트 구독, 순번, 초기 스냅샷 상태를 새로 생성합니다. 화면도 새 스냅샷으로 재구성합니다. 자동 Ack는 해제 상태로 시작하며 운영자가 다시 활성화해야 합니다. 이전 세션에서 대기 중이던 활성화 명령은 폐기합니다.
- 주문 장부, Ack 엔진, SQLite 연결의 공개 연산을 재진입 잠금으로 보호합니다. SQLite의 고유 키와 전송 전 영속 예약을 유지하여 동일 DB를 사용하는 호출 간 중복을 차단합니다. 전송 콜백보다 먼저 응답 추적 정보를 등록하여 즉시 응답의 상태를 덮어쓰지 않습니다.
- 수량·주문 번호에 소수, 무한대, 비수치 값이 들어오면 차단합니다. 초기 스냅샷, 활성화 이전 주문과 후속 부분 갱신에 대한 자동 승인 금지를 유지합니다.
- 자동 전송 전에 감사 기록을 쓰고 디스크 동기화를 요청합니다. 기록 실패 시 전송하지 않습니다. 전송·응답·타임아웃·차단·해제도 감사 기록에 남깁니다. 네트워크 전송 뒤 기록 실패나 연결 단절은 결과 불확실로 처리하고 자동 재시도하지 않습니다.
- 화면 큐는 최대 10,000개로 제한합니다. 100밀리초 안에 전달하지 못하면 Ack를 차단하고 세션을 재연결하여 화면을 다시 동기화합니다. 과부하 중 모든 화면 이벤트의 개별 보존을 보장하지는 않습니다. 자동 조치 감사 기록과 영속 예약은 별도로 유지합니다.
- 화면은 한 번에 최대 20밀리초 동안 큐를 처리하고, 잔여 메시지가 있으면 10밀리초 후 다시 처리합니다. 메시지 순서를 유지하며 부분 갱신을 임의로 합치지 않습니다. 동기식 감사 저장은 전송 안전성을 우선하므로 실제 장비에서 지연을 측정해야 합니다.
- 순번 경고와 활동 이력은 최근 300개로 제한합니다. Ack 중복 추적은 세션당 최대 100,000개 주문까지 유지하며 한도 도달 시 신규 주문 추적과 Ack를 차단합니다. 안전성을 위해 오래된 중복 키를 임의 삭제하지 않습니다. 현재 장부의 주문·라우트와 디스크 감사 기록은 자동 삭제하지 않습니다.
- 종료 시 대기 요청을 불확실 상태로 기록하고 세션·DB·메모리 참조를 정리합니다. 화면 종료는 작업자 정리가 끝날 때까지 비동기로 기다립니다.

## 호환성과 이관

기존 관리자 JSON 키, 기본 비활성 설정, SQLite 테이블과 고유 키를 유지합니다. DB 초기화나 설정 변경은 필요하지 않습니다. 추가된 `AUDIT_FAILED` 상태는 전송 전에 감사 기록이 실패한 경우입니다. 기존 `RESERVED`, `SENT`, `UNKNOWN` 등은 자동 재시도하지 않습니다. 운영자가 EMSX와 직접 대조해야 합니다.

배포 시 `synchronization.py`도 함께 복사하십시오. 실행 중인 기존 프로그램을 정상 종료하고 기존 저널·설정·감사 기록을 보존한 뒤 교체하십시오. 재연결은 자동 Ack를 재활성화하지 않습니다. 생산 전송 승인이나 Bloomberg 권한 설정을 자동으로 변경하지 않습니다.

엔진의 기존 공개 속성은 호환성을 위해 유지합니다. 병렬 호출에서는 공개 메서드를 사용하고 `orders`, `seen`, `pending` 등의 내부 컬렉션을 직접 변경하지 마십시오. 관리자 설정도 실행 중 다른 스레드에서 직접 변경하지 마십시오. 알림·전송 콜백은 상태 잠금 안에서 순서대로 실행되므로 다른 스레드의 엔진 호출 완료를 기다리는 콜백은 사용하지 마십시오.

서로 다른 PC와 별도 DB 사이의 중복 방지는 제공하지 않습니다. 승인된 단일 전송자를 유지하십시오. 감사 파일은 계좌 정보의 전체 사본 대신 환경·팀·주문 번호·조치·시각·결과를 기록합니다. 파일 보관 기간과 접근 권한은 데스크 운영 정책에 맞게 관리해야 합니다.

## 검증

프로젝트 폴더에서 Python 3.10 이상으로 실행합니다.

```bash
python -m unittest discover -s tests -v
```

기존 45개와 추가 14개, 총 59개 테스트가 통과했습니다. 추가 검증은 동시 중복 호출 2,000회, 공유 SQLite 예약 경합, 즉시 응답, 감사 저장 실패, 응답 시간 초과, 종료 후 호출, 숫자 검증, 추적 한도, 큐 과부하, 지수 재연결, 중지 응답, 오프라인 데모 스냅샷, 병렬 장부 갱신 10,000건, 실제 파서를 거치는 모의 구독 버스트 5,000건과 단절·정리를 포함합니다. 이는 처리량이나 지연 시간의 운영 보증 수치가 아닙니다.

블룸버그 터미널 및 Windows 화면 환경이 없는 Linux에서 검증했습니다. 실제 BLPAPI 세션, 전송 권한, SellSideAck, Windows 실행 파일과 화면 동작은 검증하지 않았습니다. 배포 전 승인된 BETA 환경에서 연결 단절·복구, 화면 응답성, 감사 파일 권한, 피크 부하와 실제 응답을 확인해야 합니다. 테스트는 실제 주문을 승인하거나 외부로 전송하지 않습니다.

## 2.5.1 모니터링 초기 구독·파싱 오류 격리

- 제공 로그에서 기본 Order 구독 거부와 실패 사유 잘림을 확인했습니다.
- 초기 기본 필드 집합을 복구하고 신규 표시 필드를 초기 수신 완료 후 별도 구독으로 분리했습니다.
- 선택 구독 거부·개별 필드 파싱·처리 지연 경고가 전체 Ack 해제를 유발하지 않도록 격리했습니다.
- 영향을 받은 불완전 Order의 자동 재시도는 차단하고 실제 연결·순번·저널 안전 장치는 유지합니다.
- 전체 실패 사유·요청 ID·파싱 스택을 순환 진단 파일에 저장하고 화면 경고와 구분합니다.
- 기본 테스트 73개와 신규 12개, 총 85개가 통과했습니다. 실제 Bloomberg 재검증은 필요합니다.

- 배경 태그 충돌을 제거하고 전용 1.8초 두 음 경보 및 Windows 패키지 포함을 추가했습니다.

## 2.6.5 자동 Ack 배치 전송

- 적격 신규 Order를 10밀리초 동안 수집하고 최대 50개를 한 `SellSideAck` 요청으로 제출합니다. 50개 이상은 즉시 분할하며 이전 응답을 기다리지 않습니다.
- 수신 루프 한 회전당 한 요청·최대 20개 미응답 요청으로 전송량을 제한하고, 다음 수신 대기는 배치 기한에 맞춰 줄입니다. `nextEvent(0)`의 무한 대기는 사용하지 않습니다.
- 잠금 내 사전 검증·고유 키 예약·응답 등록 순서를 유지합니다. 취소·삭제·파싱 오류 Order와 중지·해제 시 미전송 큐를 제외합니다.
- 영속 예약·상태 변경을 배치 트랜잭션으로 묶고 감사 파일은 배치 ID·상관 ID·전체 구성원 목록을 단계별로 동기화합니다. Event Log는 배치 건수와 상태를 요약하고 개별 Order 표시는 유지합니다.
- 부분 성공 응답의 조기 확정을 방지하고 같은 이벤트의 오류 응답을 우선합니다. `ErrorInfo`와 요청 실패도 처리하며 불확실한 배치 전체를 수동 대조 대상으로 남깁니다.
- 기존 설정·DB 스키마·단건 전송 콜백 호환성을 유지합니다. 새 의존성 없이 Windows 실행 파일 버전을 2.6.5로 올렸습니다.
- 총 154개 테스트로 동시 중복·대량 전송·중지·권한 재검증·감사 실패·예약 충돌·부분 응답·타임아웃을 검증했습니다. 실제 Bloomberg 배치와 Windows 실행 파일은 미검증입니다.

## 2.6.6 전체 대기 목록 단일 요청 강제

- `on_order`의 즉시 단건 전송·`_send_ack`·단건 콜백 대체 경로와 50개 분할을 제거했습니다. 전송 시점의 적격 대기 목록 전체를 한 배열로 만들어 `sendRequest`를 한 번 호출합니다.
- 이미 도착한 이벤트를 먼저 반영하며, 50밀리초의 신규 Order 수신 공백 또는 첫 대기 건 기준 250밀리초를 수집 종료 기준으로 사용합니다. 연속 이벤트 처리는 회전당 25밀리초로 제한합니다.
- 잠금 내 수집·검증·영속 예약·전송과 기존 중복·취소·권한·장애 차단 조건을 유지했습니다. 배치 콜백이 없거나 서비스가 거부하면 단건으로 다시 제출하지 않습니다.
- 진단 로그에 실제 API 경계의 건수·상관 ID·`sendRequest=1`을 기록합니다. 시작 Event Log에 버전 2.6.6을 표시합니다.
- 전송·응답 상태도 구성원 전체를 담은 화면 큐 메시지 하나로 전달하여 Order별 큐 적재와 표시 지연을 줄였습니다.
- 기존 생성자 `send_func` 인수는 접수만 합니다. 내부 사용자는 `batch_send_func(sequences, cid)`와 수신 루프의 `flush_batch()`로 이관해야 합니다. 설정·DB·의존성 이관은 필요하지 않습니다.
- 총 165개 테스트를 통과했습니다. 500개 개별 이벤트에서 API 호출 1회, 분리 수신·동시 잠금·취소·연결 단절·화면 일괄 갱신을 검증했습니다. 실제 Bloomberg 및 Windows 실행 파일은 미검증입니다.

## 2.6.7 Windows 빌드 테스트의 로그 파일 잠금 수정

- 작업자 종료 후 진단 핸들러가 전역 Logger에 남아 임시 폴더 삭제 시 `feed_diagnostics.log`의 `WinError 32`를 유발하는 문제를 수정했습니다.
- 진단 파일을 작업자 수명 동안 소유하고 정상 종료·SDK 가져오기 실패·초기 알림 오류·예외 종료에서 해제합니다. 재연결 중에는 유지하고 공유 작업자의 마지막 사용자가 종료될 때 닫습니다.
- 기존 외부 핸들러의 소유권을 보존하며 지연된 로그 호출로 닫힌 파일이 다시 열리지 않게 했습니다.
- 기존 배치 작업자 테스트에 실제 파일 스트림 닫힘 검증을 추가하고 수명·공유·실패 경로 테스트 7개를 추가했습니다. 총 172개 테스트를 통과했습니다.
- 버전을 2.6.7로 갱신했습니다. 설정·DB·의존성 변경은 없으며 대상 Windows 재빌드·자체 검사 결과는 별도 확인이 필요합니다.

## 2.6.8 지정 국가 필터 강화와 MOC No-Fill 제외

- Route 지연과 No-Fill 검사를 같은 허용 국가 검증 안에서 수행합니다. 지정 12개 코드 이외는 두 시간 경고에서 제외합니다.
- 국가값의 문자열·ASCII 영문 두 자리 형식을 대문자 변환 전에 검사합니다. 참조데이터 수신과 경고 계산의 정규화를 통일하여 잘못된 유니코드·복수 코드·비문자 입력을 차단합니다.
- `EMSX_NOTES` 기반 Instruction에 대소문자와 관계없이 MOC가 포함되면 라우트 후 체결·시간 검사와 No-Fill 시각·음향 경고에서 제외합니다. Route 미실행 상태의 MOC에는 아시아 Route 지연 기준을 유지합니다.
- 화면 안내에 발행국 ISO 기준과 MOC 예외를 표시하고 버전을 2.6.8로 갱신했습니다. DS290 발행국과 거래시장 지역은 다를 수 있으며 Route Closed Alert는 별도 기존 규칙입니다.
- 총 184개 테스트를 통과했습니다. 676개 영문 두 자리 조합, MOC 복합 지시, 참조 정정·무효화, 부분 갱신과 음향 해제를 검증했습니다. 실제 제보 Order의 원인은 예시 부재로 확정하지 않았습니다.
- 기존 설정·DB·의존성을 유지합니다. Windows 재빌드와 실제 Bloomberg 응답은 대상 PC에서 확인해야 합니다.
