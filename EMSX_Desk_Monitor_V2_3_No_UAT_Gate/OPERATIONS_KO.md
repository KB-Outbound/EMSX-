# 시장 상태·휴장 안내·당일 보고서

현재 버전은 2.9.0이며 2.7.0부터 로컬 시장 일정과 Excel 보고서 기능을 포함합니다.
새 런타임 패키지 설치나 시작 시 인터넷 연결은 필요하지 않습니다.
기존 자동 Ack 승인 설정·배치 전송·아시아 시간 경고·MOC No-Fill 예외는 유지합니다.

## 기본 화면과 식별 열

Routes가 기본 화면이며 Orders 화면은 생성하지 않습니다.
상단 상태 바에는 실행 환경·기관명·연결 상태·시장 요약·KST 시각만 표시합니다.
설명 문단·Sequence 진단·파일 경로·반복 상태 문구는 메인 화면에 표시하지 않습니다.
기존 조작부에서 Routes·자동 Ack·배당 확인을 나란한 탭으로 전환합니다.
Brokers·Event Log는 보기 메뉴에서 엽니다. 별도의 장문 안내 패널은 표시하지 않습니다.
Routes·자동 Ack 표에서 Account와 Ticker는 왼쪽 고정 영역에 표시됩니다.
최소 너비는 각각 180·220픽셀이며 글꼴과 실제 값의 폭에 맞춰 넓힙니다.
창 폭이 줄어도 최소 너비를 유지하고 상세 영역에 별도 공간을 남깁니다.
매우 긴 식별 값은 마우스를 올리면 원문을 확인할 수 있습니다.

기본 열은 Account·Ticker·Basket Name·Side·Shares·Instruction·Line Status·ADV입니다.
여유 폭에는 Fill·Remain·Broker·Avg Price를 순서대로 표시합니다.
보기 메뉴의 **상세 열 표시**에서 Create Time·휴장 안내·Alerts 등 전체 상세 열을 펼칠 수 있습니다.
상세 열을 펼친 뒤에도 Account·Ticker는 고정되며 오른쪽 상세 영역만 가로로 이동합니다.
고정 영역과 상세 영역의 행 순서·세로 스크롤·선택·경고 색상은 함께 변경됩니다.
상세 열이 모두 들어가면 가로 스크롤바는 숨깁니다.

Route의 Alerts 열에는 상위 Order의 경고를 표시합니다.
**Alerts** 필터는 Route 경고·휴장 안내·ADV 강조 행에 적용합니다.
Route가 없는 Order는 Routes 행으로 생성하지 않으며 하단 Unrouted·경고 집계와
당일 보고서의 Order 현황·Event Log에서 확인합니다. Order 수신·자동 Ack·음향 경고는 계속 동작합니다.
메모는 선택한 Route의 상위 Order에 연결하며 Brokers 등 다른 화면에서는 데스크 공통 메모로 저장합니다.
배당 확인 화면에서도 선택한 Order에 메모를 연결할 수 있습니다.
**현재 화면 CSV 저장**은 현재 필터를 통과한 행의 모든 열을 저장합니다. 접은 상세 열도 포함합니다.

## 미국 T+2 배당 확인

자동 Ack 오른쪽의 **배당 확인**은 Create Time·Account·Ticker·Qty·ISO·Instruction·Basket Name·Dividend Ex Date만 표시합니다.
미국 T+2 후보 중 **KST 날짜의 다음 NYSE 영업일**이 배당락일인 행을 상단에 고정하고 강조합니다.
주말·NYSE 휴장을 건너뛰며 2026-10-30 금요일의 대상은 2026-11-02 월요일입니다.
**Alerts**를 켜면 위험 행만 표시합니다. Broker 검색은 이 화면에 적용하지 않습니다.
일정이 없거나 지원 기간 밖이면 판정을 보류하고 하단의 **배당 일정 확인**에서 상태를 확인합니다.
필드·휴장 기준·CSV·일지·DEMO는 [배당 확인 안내](DIVIDEND_KO.md)를 참조하십시오.

## 운영 설정과 상태 확인

**설정**에서 실행 환경·구독 팀·Broker 검색·Route 지연 및 No-Fill 기준·ADV 기간·알림음을 조정합니다.
모니터링 중에는 기존과 같이 실행 환경과 구독 팀을 변경할 수 없습니다.
Route 지연은 FIX 수신 상태에서 라우트가 없는 경우이며 No-Fill은 라우트 후 체결이 0인 경우입니다.
두 시간 경고는 지정 아시아 12개 발행국 ISO에만 적용하고 MOC는 No-Fill에서 제외합니다.
기존 관측 시간 기준과 음향 재알림 규칙은 유지합니다.

자동 Ack 버튼은 현재 활성·해제·요청 대기 상태를 표시합니다.
활성 상태에서 누르면 즉시 해제를 요청하며 새 활성화는 기존 권한 검사와 전송 확인을 거칩니다.
대기 중에는 반복 활성화를 막습니다. **설정 → 자동 Ack 조건**에서 차단 사유를 확인할 수 있습니다.
연결 오류는 상단 상태, 일지 기록 실패는 하단의 짧은 표시로 알립니다.
원문과 선택 필드·파일·세션 진단은 **연결·기록 상태**, **설정 파일 위치**, **Event Log**에서 확인합니다.

## 시장 상태 패널

우측 시장 배지는 개장·미확인 시장 수를 초당 한 번 갱신합니다.
배지를 누르면 26개 시장의 상태·현지 시각을 별도 창에서 확인할 수 있습니다.
일반 상태는 흰색·회색으로 표시하고 확인된 휴장은 붉게 표시합니다.
시장을 클릭하거나 국가 선택창을 바꾸면 대표 거래소와 정규장 현지/KST 구간,
향후 7일 내 다음 휴장일을 확인할 수 있습니다. 주말의 휴장 여부도 달력으로 판정합니다.
장전은 정규장 시작 전 60분의 참고 준비 구간이며 거래소별 실제 주문 접수 개시를 뜻하지 않습니다.

Bloomberg의 실시간 거래소 운영 상태·임시 폐쇄·종목 거래 정지·실제 라우트 가능 여부를 조회하는 기능은 아닙니다.
달력 범위 밖과 일정이 없는 시장은 평일이어도 개장·휴장으로 추정하지 않고 확인 필요로 표시합니다.
새 공지·임시 휴장은 아래 로컬 지정으로 반영할 수 있습니다.

## Order의 장 상태와 휴장 안내

Routes의 상세 열에는 Market, 장 상태, 휴장 확인을 표시하며 일일 보고서의 Order·Route에도 반영합니다.
장 상태는 현재 시간표의 참고 정보이며 주문의 Line Status·체결량·Alerts와 별도로 계산합니다.
정규장 시작 전·종료 후·점심시간이라는 이유만으로 주문별 휴장 경고나 행 강조를 만들지 않습니다.
일정이 없거나 읽기에 실패한 경우에도 휴장으로 추정하지 않고 장 상태를 확인 필요로 표시합니다.

달력에서 실제 휴장일 또는 주말로 확인한 경우에만 활성 주문에 `⚠ [JP] 금일 휴장일 확인 필요` 형식의 안내를 표시합니다.
Cancel·Filled·Completed·Expired·Rejected·Deleted 및 잔량이 0인 완료 주문은 제외합니다.
Partial fill·No fill 자체는 휴장 판정 근거가 아니며 기존 Route 지연·No-Fill·ADV 강조는 유지합니다.
기존 Alerts만 표시 필터에서도 실제 휴장 확인 행을 볼 수 있습니다.
시장 안내는 별도 건수로 집계하며 기존 Route 지연·No-Fill 음향 경고에 추가하지 않습니다.
자동 Ack 권한·대상 조건을 변경하거나 주문을 자동 라우팅하지 않습니다.

기본 시장 선택은 기존 DS290 **발행국의 대표 거래소** 기준입니다.
ADR·복수 상장·다른 거래소 종목은 발행국과 실제 거래시장이 다를 수 있습니다.
판정 기준은 내부 메타데이터로 보존하며 주문별 안내에는 기준 설명을 덧붙이지 않습니다.
실제 거래시장으로 확인한 종목은 로컬 설정의 `security_markets`에 지정하십시오.
이 지정은 시장 안내에만 사용하며 기존 아시아 12개 ISO의 시간 경고 기준을 변경하지 않습니다.
휴장 날짜는 해당 시장의 현지 날짜이며 KST 날짜와 다를 수 있습니다.

## 로컬 캘린더 지정

설정 파일은 `%LOCALAPPDATA%\EMSX_Desk_Monitor_HDGB\market_calendar_overrides.json`입니다.
필요한 경우 배포 소스의 `market_calendar_overrides.example.json`을 이 위치로 복사합니다.
기존 파일이 있으면 그 내용을 보존하십시오. 날짜는 현지 날짜, 세션은 현지 24시간 시각입니다.
아래 예시는 NYSE의 확인된 2026년 성탄절 휴장·추수감사절 다음 날 조기 폐장과 종목 시장 지정 형식입니다.

```json
{
  "schema": 1,
  "security_markets": {
    "BABA US Equity": "US"
  },
  "days": {
    "US": {
      "2026-12-25": {"closed": true, "reason": "성탄절 휴장"},
      "2026-11-27": {
        "closed": false,
        "sessions": [["09:30", "13:00"]],
        "reason": "조기 폐장"
      }
    }
  }
}
```

`closed: false`이면 최소 한 개의 유효한 세션이 필요합니다.
점심이 있으면 오전·오후 세션을 따로 적습니다. 중복·역순·잘못된 시각은 적용하지 않습니다.
저장 후 **시장 배지 → 새로고침**을 누르십시오. 실행 중에는 5분마다 로컬 파일을 다시 읽습니다.
파일이 손상되거나 읽기 오류가 나면 패널과 주문의 현재 캘린더 상태를 확인 필요로 전환합니다.
이전 휴장 배지는 지우고 기존 체결·Route 경고는 유지합니다.

전체 일정 재생성 도구는 `tools/generate_market_calendar.py`입니다.
별도의 준비 환경에서 exchange-calendars 4.13.2, tzdata 2026.5 및 해당 라이브러리 의존성을 사용합니다.
이 도구와 pandas 등 생성용 패키지는 앱 실행·Windows EXE 빌드에 필요하지 않습니다.
미발표 일정을 임의로 연장하지 않으며 새 데이터 생성 후 테스트와 EXE 재빌드를 수행해야 합니다.

## 일지와 트레이더 메모

관측 기록은 `%LOCALAPPDATA%\EMSX_Desk_Monitor_HDGB\desk_journal.sqlite3`에 보존합니다.
화면의 500줄·메모리 활동 300개 제한과 별개로, 본 기능을 실행한 동안 수신한
Order·Route 갱신, 자동 Ack 상태, 세션 이벤트, Event Log와 Alert 표시 시작·해제를 저장합니다.
표시 해제는 경고가 현재 표시되지 않는다는 의미이며 체결·문제 해결을 보증하지 않습니다.
자동 Ack의 원본 영속 감사는 기존 `ack_audit.jsonl`을 별도로 사용합니다.

**메모 작성**에서 작성자·내용을 입력합니다. 선택한 Order·Route가 있으면 해당 Order와 연결하고,
선택이 없으면 데스크 공통 메모로 저장합니다. 이 메모는 EMSX 고객 Instruction을 변경하지 않습니다.
메모 저장 접수 후 일지 작업자가 저장하며 정상 종료 시 접수한 기록을 모두 저장하고 닫습니다.
일지 파일은 자동 삭제하지 않습니다. 일지와 SQLite WAL 파일의 보관·백업은 기존 내부 보관 정책에 따릅니다.

일지는 별도 작업자가 한 트랜잭션에 묶어 저장합니다.
대기열 초과·디스크 오류는 화면에 표시하며 초과 접수를 성공으로 표시하지 않습니다.
이전 버전 사용 중이거나 앱을 실행하지 않은 시간의 Route·No-Fill 이력을 소급 생성하지 않습니다.

## 당일 일지/로그 내보내기

상단 **일지 내보내기**를 누르고 내부 저장 폴더를 선택합니다.
현재 KST 날짜와 선택한 환경·구독 팀의 Excel 파일을 생성합니다.
화면 검색·Account·Broker·Basket 필터와 무관하게 관측 일지를 내보냅니다.
Order·Route 현황은 오늘·전일 생성 주문의 요청 당시 상태이며 화면의 날짜 선택과 별개입니다.

시트는 요약, Order 현황, Route 현황, Event Log, 자동 Ack, 트레이더 메모, 시장 상태의 7개입니다.
시각은 KST와 시간대를 명시하고 메모·Instruction·고객 Account·배치 ID·상관 ID·전체 Order 목록을 보존합니다.
일지·감사의 시간은 모니터 관측·작업 시각이며 FIX 원문의 송수신 시각을 새로 증명하지 않습니다.
자동 Ack의 API 정상 응답도 기존과 같은 최종 상태 미확인 기록입니다.

보고서 요청 이전 접수 기록을 먼저 저장하고 읽기 전용 연결에서 생성합니다.
보고서 작성 중에도 새 일지는 계속 접수·저장합니다. 일지는 1,000건 단위로 읽고 시트도 순차 작성합니다.
Ack 감사 파일은 요청 당시의 파일 크기까지만 읽습니다.
손상·작성 중인 감사 행과 일지 오류는 요약의 확인 사항에 표시하고 저장 후 안내합니다.
보고서가 당일 전체 EMSX 원장이나 프로그램 미관측 시간까지 완전하다고 보증하지 않습니다.

Excel·openpyxl 설치 없이 표준 라이브러리만 사용합니다.
문자열을 수식으로 실행하지 않으며 긴 Order ID를 Excel 숫자 정밀도로 절삭하지 않습니다.
긴 원문은 16,000자씩 연속 행으로 보존하고 내용 분할 열에 순서를 표시합니다.
생성 실패 시 이전 파일을 보존하며 임시 파일이 완성된 뒤 최종 이름으로 교체합니다.
Excel의 시트당 최대 행 수를 넘으면 실패를 명시합니다.

## 빌드와 검증 범위

전체 수정 소스와 `assets/market_sessions.json`을 함께 교체하고 기존 빌드 환경에서 실행합니다.

```bat
python windows_build.py build
```

기존 wheelhouse·설정·Ack DB는 유지합니다. 새 패키지 설치가 필요하지 않습니다.
시작 Event Log에는 버전 2.9.0이 표시됩니다.
총 255개 테스트로 일정·휴장·배당·경고·메모·보고서와 실제 Tk 표의 고정 열·이동·선택·CSV·보기 메뉴·설정 창을 검증했습니다.
UI 검증은 Linux 가상 화면에서 수행했습니다. 그래픽 서버가 없는 Linux에서는 UI 검사를 건너뛰며,
Windows의 Tk 초기화 실패는 빌드 테스트 실패로 처리합니다.
별도 Excel 리더로 숫자·긴 ID·문자열 수식 차단·머리글 고정도 확인했습니다.
실제 Windows 화면·Excel·Bloomberg 세션과 각 거래소의 최신 임시 공지는 대상 PC에서 확인해야 합니다.
